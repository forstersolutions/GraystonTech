Evidence outputs

Every stage leaves something the next decision can use.

The review packet is designed for engineers, operators, and owners who need to know what is reachable, what changed, and whether the system should ship.

01 / Model

Threat model + abuse cases

Assets, identities, trust boundaries, data movement, attacker goals, business impact, and the scenarios most worth attacking.

02 / Discover

Attack-surface register

Architecture, source, cloud, agents, dependencies, configuration, secrets, integrations, and the exposed paths between them.

03 / Validate

Evidence-backed findings

Reproduction, preconditions, exploit chain, reachable impact, severity rationale, affected contracts, and practical remediation.

04 / Close

Remediation + retest packet

Root-cause fix, code or configuration evidence, original-path rerun, regression protection, residual risk, and closure state.

05 / Decide

Release recommendation

An explicit go, conditional go, or no-go decision tied to the evidence, owner, compensating controls, telemetry, and rollback path.

Responsible disclosure

Report security issues clearly and non-destructively.

Include the affected URL, reproduction steps, browser or device context, screenshots if useful, and potential impact. Do not access, change, delete, download, or exfiltrate data that is not yours. Do not run denial-of-service, social engineering, credential, or destructive tests. Grayston does not currently operate a paid bug bounty program.
